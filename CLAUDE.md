# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

SeqVerse is a JUCE 7.0.9 audio plugin (C++17) that generates MIDI notes and is growing into a generative MIDI sequencer (it was called GenerativeMidi before). It ignores incoming MIDI. While the host transport is playing, every step of the host's PPQ timeline (`Step Rate`, 1/32 to 1/1 with triplets) has a chance (`Chance`, 0-100 %) of playing one note from the pool of notes of the selected `Key` and `Scale` over `Octaves` (1-8) octaves from `Low Octave`, cut off at octave 7, plus (with `Octave Note` on Include, the default) the root of the octave above the range as the top note, so one octave of C major is C D E F G A B C, for the selected `Note Length` (1/32 to 1/1). `Play Mode` is either Arpeggio (walks the pool in the `Arp Direction`) or Random. `Swing` delays every odd step, `Velocity` and `Velocity Variation` set the velocity, `Channel` the MIDI channel, and `Seed` makes the random choices repeatable (0 is "Auto", different every time). `Cycle Length` (0.5 to 64 beats in half-beat steps, default "Off") makes the output repeat: the step grid restarts every cycle and each cycle plays what the first did. `Rhythm` is either Every step (the default: each step has its `Chance`) or Euclidean: `Pulses` (0-32) are spread evenly over `Pattern Length` (2-32 steps, default 8) steps that repeat freely on the step grid (or from the start of each cycle), `Rotation` moves the pattern later, and only the onsets get their chance; the arpeggio advances by one note per onset. Defaults: C major, arpeggio up, 1/8 steps, 100 %, 1/16th notes, octave 4 only, velocity 100, channel 1, no swing. Nothing is generated while the transport is stopped, and notes still sounding are ended when it stops. There is no linter configured.

## Build

JUCE and clap-juce-extensions are **not** vendored or fetched; CMake `add_subdirectory`s them from `~/SDKs/JUCE` and `~/SDKs/clap-juce-extensions` and fails at configure time if either lacks a `CMakeLists.txt`. Override with `-DJUCE_DIR=...` / `-DCLAP_JUCE_EXTENSIONS_DIR=...`. Pinned versions are noted at the top of `CMakeLists.txt` (JUCE tag 7.0.9, clap-juce-extensions `54d83e1`).

```
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build --target SeqVerse_VST3
cmake --build build --target SeqVerse_CLAP
```

Artefacts land in `build/SeqVerse_artefacts/Release/{VST3,CLAP}`. The JUCE and clap-juce-extensions trees are added `EXCLUDE_FROM_ALL`, so only what the plugin targets depend on gets built from them.

## Testing

`tests/clap_test_host.cpp` is the scripted CLAP test host: a small headless host (no GUI, no audio device) that `dlopen`s the built `.clap` from the build tree, runs scenarios through `process()` and checks the MIDI that comes out. It never touches `~/.clap`. Registered as the CTest test `clap_host_generator`.

```
cmake --build build --target SeqVerse_CLAP clap_test_host
ctest --test-dir build --output-on-failure
./build/clap_test_host build/SeqVerse_artefacts/Release/CLAP/SeqVerse.clap   # verbose, per-check output
```

Each scenario creates a fresh plugin instance, sets parameters by name and text through the CLAP params extension (`text_to_value`, so scale names in the test must match the choice strings exactly), drives the transport (120 BPM, 48 kHz, so a 1/8th step is 12000 samples), and compares note-ons and note-offs with hand-written expectations. Scenarios run with `Octave Note` set to Exclude unless they set `octaveNote = true` (or the parameter) themselves, because most were written for one octave of seven notes and are about something else; the "default settings" and "octave note" scenarios test the real default. It covers: the parameter ranges reported to the host, choices picked by raw index the way a host does, the defaults, stopped and missing transport, a stop while a note sounds, starting between two steps, every one of the 15 arp directions (hand-written patterns, and for pools of 1 to 96 notes each stays inside the pool and plays all of it), the same note played again while it sounds, random mode and every scale, chance 0, ignored MIDI input, step rates, octave ranges (including low above high), velocity and variation, channel, swing (also with steps that land on block boundaries in many ways), seeds (repeatable, different, and independent of where the transport starts), the Euclidean rhythm (patterns, rotation, lengths that drift against the bar, values a knob cannot make but a host can, restarting with each cycle, joining mid-pattern, swing and chance on onsets), cycle lengths (arp pattern, steps that do not fit the cycle, starting inside a cycle, and random choices, chance, velocity and swing repeating every cycle), the state save/load round trip, and loading a session saved by the earlier version of the state (fractions of the range). When behaviour changes, add or change scenarios in that file rather than adding a second host. A new test should be shown to fail against a deliberately broken plugin before it is trusted.

`tests/ui_test.cpp` (target `SeqVerseUiTest`, CTest test `ui_enabled_controls`) builds the real editor and processor without a host or a window, changes parameters, and checks which controls are enabled. Every control's component ID is its parameter ID, so tests find controls with `findChildWithID()`. Given a path prefix it also writes PNG snapshots, which can be looked at with the Read tool, so use it to check any layout or colour change instead of guessing:

```
cmake --build build --target SeqVerseUiTest
./build/SeqVerseUiTest_artefacts/Release/SeqVerseUiTest "$CLAUDE_JOB_DIR/tmp/editor"   # writes editor_arpeggio.png etc.
```

Only the final confirmation in Bitwig itself is manual.

## Architecture

- Only `VST3` is declared in `juce_add_plugin(FORMATS VST3)`. JUCE 7 has no CLAP format, so `clap_juce_extensions_plugin(TARGET SeqVerse ...)` wraps the same target as a CLAP (`SeqVerse_CLAP`). Format-specific behaviour should live behind JUCE's `AudioProcessor` API, not in per-format code.
- `SeqVerseProcessor` (`src/PluginProcessor.*`) is the `AudioProcessor`; `SeqVerseEditor` (`src/PluginEditor.*`) is its UI, created in `createEditor()`. `createPluginFilter()` at the bottom of `PluginProcessor.cpp` is the JUCE entry point.
- `src/Music.h` holds the musical tables (keys, scales, play modes, arp directions, step rates, note lengths), `noteNumber()`, `arpIndex()` and the per-step random generator `StepRandom`, with no JUCE dependency; the test host includes it too. The tables' order is the order of the matching parameter's choices, and a saved session stores the index, so add to the end only (see the note on state below). The 15 arp directions are all pure functions of the step number and the pool size in `arpIndex()`; the random-based ways of choosing notes (shuffle and the like) are deliberately not among them, because Random mode covers randomness.
- Generation is locked to the host's PPQ position, not to a running sample counter: a block owns the steps that start in it (an odd step starts one swing delay after its grid position), and the arp index derives from the step number, so loops and jumps keep the pattern in place. Pending note-offs are kept in block-relative samples. Within a block the note-offs are added to the `MidiBuffer` before the note-ons, which is what makes a note end before the same note restarts on the same sample.
- All the randomness of a step (chance, note, velocity variation) comes from one `StepRandom` that is always drawn from in the same order, so changing one setting does not reshuffle the others. With a non-zero `Seed` it depends on the seed and the step number only; with 0 it is seeded from a `juce::Random`.
- Cycle length is counted in half beats (0 is off). There is **no recording buffer**: with a cycle, everything about a step (note, chance, velocity variation, swing, arp position) is a pure function of its number within the cycle and of a cycle seed, so every cycle repeats the last one exactly, and there is nothing to allocate, no edge case for starting inside a cycle, and loops or jumps of the transport keep the pattern. Cycles start at multiples of the cycle length on the host timeline and the step grid restarts in each, so a cycle that is not a whole number of steps ends with a shorter last step. The cycle seed is `Seed` when set; on Auto it is rolled when the transport starts and when the cycle length changes (`autoSeed`). Because nothing is recorded, changing key, scale or octave range while cycling changes the loop live (a transposition), while changing chance or velocity variation changes which steps play and how hard. Without a cycle (Off) this path is not used. Outside a cycle the arp position is the step number on the host timeline, so a transport that starts mid-song joins the pattern where it would be. There is deliberately no "restart on play" option: an `Arp Reset` parameter existed and was removed, since a cycle length that matches the bar does the same job.
- The Euclidean `Rhythm` is a source of rhythm that is independent of how pitches are chosen (the first attempt was a third Play Mode and was removed for that reason, see git history). `music::EuclidPattern` (Bjorklund, in `Music.h`, no allocation, up to 32 steps) is rebuilt in each block that uses it, from `Pattern Length`, `Pulses` and `Rotation`, which are three ordinary parameters as in most Euclidean sequencers. The pattern runs freely on the step grid: step k of the timeline is at position k mod `Pattern Length`, so a length that is not the bar's drifts against it, and with a cycle the step number is the one in the cycle, so pattern, notes and arpeggio all start over with each cycle (a cycle that is not a multiple of `Pattern Length` cuts the last repeat short). The cycle length is deliberately not the pattern length: that was tried first and made a free-running pattern impossible without also looping the notes. Only onsets play, and the arp position is the onset number (counted from the start of the cycle, or of the timeline when the cycle is Off, so joining mid-song lands on the right note) instead of the step number, so the arpeggio does not skip notes on the rests. `Chance` still applies to each onset; the random draws are still per step, so switching rhythm does not reshuffle them. Swing follows the parity of the grid step, not of the position in the pattern. The four new parameters are added last and saved like all others, so old sessions load as Every step. The pattern for a length is a rotation the generator picks (3 in 4 is `xxx.`, not `x.xx`); users get the others with `Rotation`. There is no pattern display in the editor (the removed version had one).
- **No parameter is ever written in reaction to another one, and none has to be valid in combination with another.** The host can set any parameter at any time (automation, a generic parameter list, a loaded session), in any order and from another thread than the editor, and a listener that pushed one parameter when another changed would fight automation and be a source of threading trouble (the first version had one, for a low octave above the high one, and a second attempt limited the knobs in the editor; both were replaced). So parameters are independent, and `processBlock` makes sense of every combination: the note range is `Octaves` octaves from `Low Octave` and stops at the top octave (there is deliberately no High Octave parameter, which could end up below the low one), `EuclidPattern` limits its length, takes any pulses (more than the length plays every step) and wraps the rotation. A new setting should be shaped the same way, as a count or an amount rather than as the far end of a range, and if it cannot be, it is clamped where it is used. The editor writes a parameter only as the user's own gesture.
- `CMakeLists.txt` passes `CLAP_USE_JUCE_PARAMETER_RANGES ALL` to `clap_juce_extensions_plugin`. Do not remove it: by default the wrapper reports every parameter to the host as 0..1 while still flagging choice parameters as stepped, and a host such as Bitwig then offers only two values of a 43-entry list (the Scale selector appeared stuck on one scale). With `ALL` the host gets the real range and sends a choice's index as the value. The test host checks the reported ranges and also sends raw indices, because setting parameters by text (`text_to_value`) cannot reveal this kind of bug.
- Editor: a control that has no effect with the current settings is disabled, label included (`updateEnabledControls()` in `PluginEditor.cpp`, hooked to the play mode, chance and velocity variation controls, which the attachments also update on host changes). Arp direction needs Arpeggio mode. `Pattern Length`, `Pulses` and `Rotation` need the Euclidean rhythm. The seed needs something random: Random mode, a chance below 100 %, or a velocity variation, because an arpeggio at 100 % with a fixed velocity has nothing to seed. When a new parameter's effect depends on another, extend that function and `tests/ui_test.cpp`. The editor has a dark theme: `src/DarkLookAndFeel.h` holds the palette (`theme::`), the knob drawing (thin ring, glowing teal value arc, white end dot, dimmed when disabled) and the colours of dropdowns, popup menus, labels and value boxes. Editor code should not set colours itself (only the title does), so a restyle stays in that one file. The editor calls `sendLookAndFeelChange()` at the end of its constructor, because the sliders' value boxes are created before the sliders are children of the editor and would otherwise keep JUCE's default look. `tools/knob_styles.cpp` (target `KnobStyles`) renders sample controls in several alternative knob styles as PNGs, for trying a different look before changing the real one. The last 70 pixels of the editor are left empty because JUCE's mandatory "Made with JUCE" badge covers the bottom right corner.
- The MIDI input port stays declared but unused (`acceptsMidi()` is true), so hosts such as Bitwig still place the plugin in a note chain.
- State save/restore writes each parameter's **value** (the index of a choice, the number of an integer parameter) as an XML attribute named by its parameter ID, plus a `version` attribute (currently 2); new parameters are saved automatically, and missing ones keep their defaults. It must not store fractions of the range: a list that gets another entry would then change what a saved value means, which is what happened to the first version of the state (version 1, no attribute), stored as fractions. `setStateInformation` still reads version 1, and migrates the arp direction, which had 7 entries then (`kNumArpDirectionsInFirstVersion`). When a choice list grows it grows at the end, and never gets reordered or shortened; if a parameter's meaning has to change in another way, raise the state version and migrate in `setStateInformation`.
- The plugin is deliberately declared as an effect (`IS_SYNTH FALSE`, `IS_MIDI_EFFECT FALSE`) with MIDI in and out, and with a **silent stereo output bus and no input bus**. That bus exists because some hosts (Bitwig) do not run a plugin with no audio ports. `isBusesLayoutSupported` enforces "no input, stereo output" and must stay consistent with the constructor's `BusesProperties`.
- Plugin identity (`PLUGIN_MANUFACTURER_CODE Hjuh`, `PLUGIN_CODE Sqvs`, CLAP ID `com.henrik.seqverse`) is what hosts use to recognise saved sessions, so don't change it casually.
- `JUCE_WEB_BROWSER=0`, `JUCE_USE_CURL=0` and `JUCE_VST3_CAN_REPLACE_VST2=0` are set as compile definitions; the only JUCE module linked is `juce_audio_utils`.

## Project rules

- **Audio thread** (`processBlock`): no allocations, no locks, no UI calls, and no setting of parameters. Read parameters directly via `AudioParameterInt::get()` and `AudioParameterChoice::getIndex()`.
- **Parameter constraints:** there are none between parameters, see above: no parameter is written because of another, and `processBlock` copes with any combination. Test a new one with the values a host can send but a knob cannot.
- **Testing:** use the scripted CLAP test host before claiming something works.
- **Building:** use CMake and Ninja, and the build must produce no warnings.
- **Final step of every task:** build the `.clap`, run the CTest host test, then copy `build/SeqVerse_artefacts/Release/CLAP/SeqVerse.clap` to `~/.clap/` so it can be tested manually in Bitwig. This is standing permission, no need to ask. Copy to a temp name in `~/.clap` and `mv` it over the target, because Bitwig may have the old file loaded. Check whether Bitwig is running (`pgrep -ia bitwig`) and mention it, since it needs a plugin rescan.

## Repo conventions

- `build/` is git-ignored. Sibling checkouts under `.claude/worktrees/` are other Claude sessions' worktrees, not part of the source tree.
- The default branch is `main`, but the initial checkout is on `master`.
